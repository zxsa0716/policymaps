## 무엇을 푸는가

지자체 담당자가 새 조례를 만들 때 실제로 하는 일은 이렇다.

> 옆 동네는 이걸 어떻게 만들었지? → 구글 검색 → 자치법규정보시스템에서 하나씩 열람
> → 담당자에게 전화 → 상위법 근거가 맞는지 다시 확인

**조례를 직접 만드는 전국 기초자치단체 227곳이 같은 일을 따로따로 반복한다.** 그러면서도
"우리와 비슷한 지자체 10곳 중 7곳에는 있는데 우리엔 없는 조례"는 아무도 알려 주지 않는다.
상위법이 조례로 정하라고 위임했는데 아직 만들지 않은 것도 마찬가지다.

이 시스템은 **전국의 조례·상위법·예산·의안·행정경계를 하나의 그래프로 엮어**
그 질문에 답한다. 답에는 항상 **근거 경로와 원문 링크**가 붙고,
**어디까지가 확인이고 어디부터가 추정인지**를 수치로 함께 공시한다.

```
"경기도 광명시에 없는 조례를 찾아 줘"
   └→ 유사 지자체 10곳 선정 (인구·재정·산업 구조)
       └→ 그 10곳이 가진 조례 집합 − 광명시 보유 조례
           └→ 상위법 위임 근거가 있는 것부터 정렬
               └→ 각 항목마다: 어느 지자체가 언제 제정했는지 · 상위법 몇 조인지
                              · 예산이 얼마나 붙었는지 · 원문 링크
```

### 핵심 설계 판단 3가지

**1. 조례를 "텍스트"가 아니라 "그래프 노드"로 본다**
제목이 달라도 같은 상위법에 위임받고, 같은 분야에 속하고, 비슷한 이웃을 가진 조례는
구조적으로 같은 정책수단이다. 그래프 임베딩은 제목 유사도가 못 잡는 이 관계를 회수한다.

**2. 위임관계를 4경로 합집합으로 뽑는다**
조례 본문의 「법률명」 낫표 인용, 국가법령정보의 위임법령 API, 조문 단위 참조,
법령명 이름해소 — 네 경로를 합쳐 421,627건을 만들었다.
이름해소로 붙인 605,424건은 추론이므로 그래프에서 `resolved_by="name-match"` 로 구분 표기한다.

**3. 검증 상태를 데이터 스키마에 넣는다**
"사람이 대조함 / 기계 전수확인 / 확률적 추정"을 행마다 기록하고 화면에 배지로 띄운다.
숨기지 않는 대신, 무엇을 믿고 무엇을 의심할지 사용자가 판단할 수 있다.

## Agent 구조

`자치법규 정책지도.agent` 는 별도 챗봇을 붙인 것이 아니라, 현재 보고 있는 화면의
데이터와 정책지도 도구 결과를 함께 읽는 **화면 인식형 정책 분석 에이전트**다.
목표는 "대화로 질문 → 필요한 화면/근거를 찾아 이동 → 발표 가능한 답변으로 정리"다.

```mermaid
flowchart LR
    U[사용자 질문<br/>또는 패널 Q&A 클릭]
    B[viz/public/js/agent.js<br/>현재 route · data mode · 선택 지역 · 패널 텍스트 수집]
    P[/ai/chat 또는 Vercel api/chat.py<br/>API 키를 숨기는 프록시]
    C[viz/ai_core.py<br/>도구 계획 · fixture 로딩 · 근거 카드 생성]
    G[Gemini<br/>GEMINI_API_KEY가 있을 때]
    F[로컬 요약 폴백<br/>키/네트워크 오류 시]
    R[답변 · 근거 카드 · 다음 실행 버튼 · handoff memory]

    U --> B --> P --> C
    C --> G --> R
    C --> F --> R
```

### 구성 파일

| 파일 | 역할 |
|---|---|
| `viz/public/js/agent.js` | 우하단 AI 패널, 빠른 질문, 현재 화면 컨텍스트 수집, 답변/근거/다음 실행 버튼 렌더링 |
| `viz/ai_core.py` | 에이전트 공통 코어. 질문 의도 판별, 필요한 데이터 로딩, Gemini 호출, 로컬 폴백 답변 생성 |
| `viz/serve_ai.py` | 로컬 개발용 정적 서버 + `POST /ai/chat` 프록시 |
| `api/chat.py` | Vercel 배포용 서버리스 AI 프록시. 브라우저가 직접 Gemini 키를 들고 있지 않게 한다 |
| `viz/public/js/components.js` | 패널 제목 옆 Q&A 버튼에서 `agent:panel-question` 이벤트 발생 |
| `viz/public/js/scoring.js` | 정책 후보별 도입 가능성 의사결정 보조 점수 계산 |

### 작동 방식

1. 사용자가 질문하거나 패널의 `Q&A` 버튼을 누르면 `agent.js` 가 현재 route,
   `mock/real` 데이터 모드, 기준일, 선택 지자체, 현재 패널의 제목과 텍스트를 묶는다.
2. 브라우저는 이 컨텍스트를 `/ai/chat` 으로 보낸다. API 키는 브라우저 코드와 GitHub에
   넣지 않고, 로컬 `.env` 또는 Vercel 환경변수에만 둔다.
3. `ai_core.py` 는 질문을 보고 필요한 도구를 계획한다. 예를 들어 도입 가능성 질문이면
   격차분석·유사 지자체·정책 확산·조례-예산 실효성 fixture를 함께 읽는다.
4. 읽은 데이터는 근거 카드(`evidence`), 도구 실행 흔적(`tool_trace`), 다음 화면 버튼
   (`actions`), 후속 질문용 기억(`handoff`)으로 정리된다.
5. `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY` 가 있으면 Gemini가 이 구조화된 근거를
   자연어 답변으로 바꾼다. 키가 없거나 호출이 실패하면 같은 근거로 로컬 요약 답변을 낸다.

### 주요 기능

| 기능 | 설명 |
|---|---|
| 화면 인식 질문 | 현재 화면, 선택 지역, 데이터 기준일, 패널 텍스트를 함께 보내 "이 패널을 설명해줘" 같은 질문에 답한다 |
| 패널 Q&A | 복잡한 표·차트 제목 옆 버튼을 누르면 질문 입력 없이 해당 패널 설명 요청이 자동 실행된다 |
| 도구형 답변 | 답변과 함께 격차분석, 정책 확산, 실효성, 검색, 지역 상세 화면으로 이동하는 버튼을 제안한다 |
| 근거 카드 | 답변에 사용한 fixture 요약과 기준일을 별도 카드로 노출해 발표자가 근거를 되짚을 수 있다 |
| 후속 질문 기억 | 한 번 구미시·맨발걷기를 물으면 다음 질문에서 지역/정책 키워드를 이어받는다 |
| 도입 가능성 스코어 | 정책 후보에 0~100점의 "의사결정 보조 점수"를 붙이고 점수순 정렬을 제공한다 |
| 안전 폴백 | Gemini 장애·키 누락·네트워크 오류 때도 규칙 기반 요약으로 사이트 시연이 멈추지 않는다 |

### 도입 가능성 스코어

스코어는 AI의 주관 판단이 아니라 화면 데이터에서 계산하는 **의사결정 보조 점수**다.
조례 도입 필요성의 확정 판단이나 법적 판단이 아니며, 후보를 정렬하고 발표 우선순위를
잡기 위한 참고값이다.

| 항목 | 최대점 | 의미 |
|---|---:|---|
| 유사 지자체 보유 | 40 | 비슷한 지자체가 얼마나 많이 이미 갖고 있는지 |
| 폐지 위험 | 20 | 폐지 사례가 적을수록 높음. 폐지 조례는 선례 추천에서 제외 |
| 정책 확산 | 20 | 전국 채택률·확산 단계가 높을수록 도입 논거가 강함 |
| 예산 근거 | 20 | 조례-예산 연결이 있으면 가점. 단, `verified=1` 만 확인됨이고 나머지는 추정 연결 |

### 정확성·보안 규칙

- 모든 수치 답변에는 `as_of_date` 기준일을 함께 언급한다.
- 조례-예산 연결은 `verified=1` 만 "확인됨"으로 쓰고, 나머지는 "추정 연결"로 말한다.
- 폐지 조례는 선례로 추천하지 않고 위험 신호로만 설명한다.
- `mock` 데이터일 때는 가상데이터 배너와 샘플 기준 설명을 유지한다.
- Gemini API 키는 `.env`, `system/.env`, Vercel 환경변수에만 둔다. `viz/public/` 또는
  GitHub에 커밋하지 않는다.

로컬에서 Gemini까지 붙여 확인하려면 저장소 루트의 `.env` 에 키를 넣고 다음처럼 실행한다.

```bash
python viz/serve_ai.py --port 8742
```

브라우저에서 `http://127.0.0.1:8742/viz/public/index.html` 로 접속하면 정적 화면과
`/ai/chat` 프록시가 함께 동작한다. 단순 정적 서버(`python -m http.server`)로 열면
화면은 보이지만 AI 답변은 로컬 요약 또는 연결 실패 상태로 제한될 수 있다.

| **확산·커뮤니티 분석** | EHA 위험모형, 커뮤니티 탐지, 유사도 방법 비교 |
| **국회 표결** | 의안별 정당 찬반 분해 |
| **조문 전문검색** | GraphRAG 하이브리드 검색 |
| **검증 공시** | 무엇을 어떤 근거로 확인했는지 전면 공개 |
| **조례 상세** | 조문 본문\* + 상위법 + 예산 + 유사 조례 (\*본문은 로컬 완전판 한정) |
| **법령 상세** | 법령 조문 + 이 법에 위임받은 전국 조례 |

## 분석 방법론

전부 **numpy 단독 구현**이다. PyTorch·DGL 같은 무거운 프레임워크 없이 돌아간다.
다만 행정경계 재수집과 Queen 인접 재계산에는 shapely>=2.0 이 필요하다(`pip install -e system[geo]`). 없으면 정점 일치 폴백으로 동작하나 인접 쌍 수가 달라진다.

| 방법 | 구현 | 쓰임 |
|---|---|---|
| **node2vec** | `neural/embeddings.py` | 그래프 구조 임베딩 (128차원) |
| **metapath2vec** | `neural/embeddings.py` | 이종 그래프 메타패스 임베딩 (64차원) |
| **GraphSAGE** | `neural/gnn.py` | 귀납적 임베딩 + JK-Net concat 으로 과평활 해소 (132차원) |
| **GraphRAG** | `rag/index.py`, `rag/retrieve.py` | BM25 + Dense 를 RRF(k=60)로 융합하고 그래프로 확장 |
| **EHA 사건사분석** | `analytics/eha.py` | 이산시간 위험모형 — 조례 채택 확률의 결정요인 |
| **Moran's I / LISA** | `analytics/spatial.py` | 조건부 순열검정 999회 + BH-FDR 다중비교 보정 |
| **로지스틱 성장곡선** | `analytics/diffusion.py` | 확산 S-곡선 적합, 경로 분해 |
| **커뮤니티 탐지** | `rag/community.py` | 정책 클러스터 식별 |
| **유사 지자체** | `analytics/peers.py` | 행안부 유사자치단체 기준 + 4가지 방법 비교 |

법령 그래프는 **ELI · Akoma Ntoso · FRBR** 국제 표준에 대조해 설계했다
(`system/policymap/standards.py`, [docs/14](docs/14_법령그래프_표준_및_온톨로지.md)).

## 실행 방법

### 1) 그냥 보기 — 설치 불필요

**[https://policymaps.vercel.app/](https://policymaps.vercel.app/)**

정적 배포본이라 서버가 필요 없다. 조문 본문(490MB)만 빠져 있고 나머지는 전량이다.

### 2) 로컬에서 정적 사이트 띄우기

```bash
git clone https://github.com/zxsa0716/policymaps.git
```

```bash
cd policymaps && python -m http.server 8000
```

브라우저에서 `http://127.0.0.1:8000/viz/public/index.html`

> 웹 루트는 **저장소 루트**여야 한다. `viz/public/` 에서 서버를 띄우면
> 데이터 경로(`../../system/data`)에 접근할 수 없어 화면이 비어 보인다.

### 3) 완전판 — 조문 본문 236만 건까지

`system/data/policymap.db`(약 5.4GB)가 필요하다. 용량 때문에 깃허브에 올리지 않는다.

```bash
run_full.bat
```

`http://127.0.0.1:8743/viz/public/index.html?full=1`

DB가 있으면 조문 본문 전량 열람, 임의 질의 전문검색, 임의 조례 서브그래프·신경망
유사도가 모두 열린다. **API 키는 필요 없다** — 수집이 끝나 외부 호출을 하지 않는다.

### 4) 데이터 새로 수집하기

```bash
cp system/.env.example system/.env
```

키 5종을 채운 뒤:

```bash
python -m policymap init && python -m policymap collect --source law,ordin,na_bill,budget
```

```bash
python -m policymap parse && python -m policymap build && python -m policymap export
```

### 5) MCP 서버 — Claude 등 AI 도구에 연결

```bash
python -m policymap mcp
```

14개 tool 을 노출한다 — `recommend_ordinances`, `gap_analysis`, `explain_path`,
`semantic_search_ordinance`, `spatial_autocorrelation`, `diffusion_timeline`,
`ordinance_effectiveness`, `bill_vote_breakdown` 등.

## 검증

이 시스템은 **틀릴 수 있는 부분을 숨기지 않는다.**

| 검증 | 결과 |
|---|---|
| 원문 확보 | 조례 **199,695 / 199,858 (99.92%)** 가 공식 원문에 연결 |
| 위임 인용 대조 | 위임 **421,627건 전건**을 기계 대조 → 인용 조문 존재 확인 **182,784건(43.3%)** · 불일치 28,309건(6.7%) · 확인불가 210,534건(49.9%) |
| 사람이 직접 대조 | 1,205건 — **법령 627 · 기관 578**. 조례는 조문 수준 대조를 하지 않았다(0건) |
| 조례↔예산 링크 표본검증 | 층화표본 584건 수작업 판정 — 전체 정밀도 64.9%. 신뢰도 0.8 이상 구간은 **93.2%** 이나 그 구간이 전체 183,145건 중 42,872건(23.4%)이다 |
| 시간 무결성 자동감사 | 7,060건 규칙 위반 탐지·보정 |
| 공간자기상관 | 조건부 순열검정 999회 + BH-FDR (조례 수 Moran's I = 0.3655, p = .001, n=227 전수) |

> 그래프 엣지 수(ADJACENT_TO 1,098)는 2026-08-21 빌드 기준이다. 2026-09-01 행정경계 갱신으로 DB의 인접 쌍은 1,310으로 늘었으며, 그래프 재빌드 시 반영된다.

화면의 **[검증 공시]** 탭에서 위 수치의 분해와 방법을 전부 공개한다.
표본검증 설계와 판정 기준은 [docs/17](docs/17_링크_표본검증_보고서.md) 에 있다.
